## 3. Дүгнэлт

1. Энэхүү лабораторийн ажлаар k6 хэрэгслийг ашиглан `https://test.k6.io` веб сайтын гүйцэтгэлийн үндсэн хэмжүүрүүдийг бодитоор хэмжиж туршлаа.
2. 30 VU бүхий 1 минутын ачааллын туршилтаар нийт 2116 HTTP хүсэлт сервер рүү амжилттай илгээгдэж, Throughput дунджаар **34.49 req/s** боловсруулагдсан.
3. Туршилтын явцад хийгдсэн 1058 удаагийн `status 200` шалгалт (check) 100% амжилттай биелсэн.
4. Системийн алдааны хувь (`http_req_failed`) 0.00% байж, сервер бүх хүсэлтэд амжилттай хариу буцаав.
5. Хариу өгөх дундаж хугацаа (`avg`) 321.64 ms, медиан хугацаа (`med`) 256.35 ms, хамгийн богино хугацаа (`min`) 67.9 ms байв.
6. Нийт хүсэлтийн 90% нь 563.84 ms-ээс бага хугацаанд боловсруулагдсан боловч 95% нь 765.49 ms хүртэл уртассан байна.
7. Ачаалал нэмэгдэхэд серверийн хариу үйлдэх хугацаа (Latency) уртасдаг лекцийн онолын үзэгдэл бодитоор баталгаажлаа.
8. Скриптэд тохируулсан `p(95) < 500ms` шалгуур нь бодит гаралт (765.49 ms)-аас бага байсан тул Quality Gate ажиллаж, Threshold FAILED төлөвтэй боллоо.
9. Веб сайтын ачаалал даах чадвар сайн (алдаагүй) боловч хэрэглэгчийн хүлээх хугацааг багасгахын тулд серверийн кэш болон асуулгыг оновчлох шаардлагатайг харуулж байна.
10. k6-ийн Thresholds функцийг CI/CD автоматжуулалтад ашигласнаар гүйцэтгэлийн шаардлага хангахгүй кодыг автоматаар зогсоох боломжтойг практикт ойлгож авлаа.
